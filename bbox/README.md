# 펜 위치 grounding — 회전 박스 토큰 예측

2026-10-05 · items_handover

## 왜

측정된 실패가 **조준 오차**다. 타이밍은 맞는데 손이 엉뚱한 데 있다.

```
그리퍼 닫는 시점  t_fail 중앙값 85    (대본 close 구간 74–89)   ← 정확
펜 들림                    11/100                            ← 위치가 틀림
```

MEM(부분 관측)도 mistake(실수 조건화)도 이걸 직접 겨냥하지 않는다.

## 무엇을 예측하나 — **토큰 5개**

벡터 회귀가 아니다. subtask 문장을 생성하는 것과 **같은 메커니즘**이다.

```
State: 101 134 ...;  Mistake: false;
Pen: <loc0986><loc0394><loc0201><loc0045><loc0340>;     ← 모델이 생성
Subtask: lower the right gripper onto the pen;
Action: ...
```

| 자리 | 뜻 | 예 (ep000 f40) | 변동폭(5~95%) |
|---|---|---|---|
| 1 `cx` | 박스 중심 가로 | 616.9 px | 402 px |
| 2 `cy` | 박스 중심 세로 | 184.8 px | 191 px |
| 3 `w` | 긴 변 | 125.9 px | 63 px |
| 4 `h` | 짧은 변 | 21.1 px | 8 px (거의 상수) |
| 5 `θ` | 긴 변 기운 각 | 59.8° | 58° |

각 값을 0~1 정규화 후 1024단계. 해상도 cx **0.6 px**, θ **0.18°**.
일을 하는 건 **cx, cy, θ**. w는 거리 단서, h는 거의 상수(박스 복원·IoU 평가용).

## 왜 토큰인가 (6차원 벡터가 아니라)

| | 연속 벡터 헤드 | **토큰** |
|---|---|---|
| 물체 개수 가변 | max N + 0 패딩 + 매칭 필요 | **EOS 로 자연 처리** |
| 새 파라미터 | MLP 헤드 | **0개** |
| action expert 가 읽나 | **✗** 옆가지라 시퀀스에 없음 | **✓** KV 로 전달 |
| π0.5 | 아님 | **이것** |

`<loc0000>`~`<loc1023>` 는 PaliGemma 사전에 **이미 있다** (id 256000–257023, 각 1토큰).
검출 형식으로 사전학습돼 있어 밑바닥부터 배우지 않는다.

**각도를 cos/sin 둘로 쪼갤 필요 없다.** 그건 연속 회귀의 wraparound 문제를 푸는 기법인데,
이산 토큰에는 그 문제가 없다. (연속으로 간다면 펜은 방향 없는 축이라 `cos2θ/sin2θ` 가 맞다.)

## 라벨 — 시뮬레이터도 탐지기도 안 씀

학습 parquet 에 `pen_pose`(4×4)가 있고 `cam_high` 가 고정 카메라
(intrinsics·extrinsics 가 `gym_config.json`)라, 펜 메시(143.4×15.3 mm)의
3D 박스 8꼭짓점을 투영하면 **정확한 GT** 가 나온다.

```
/workspace/obb_labels/ep0000.npy ~ ep0999.npy    7.9 MB
(T, 6) float32 = [cx, cy, w, h, theta, visible]   cx,cy,w,h 0~1 · theta 0~pi
327,000 프레임 · 보이는 프레임 278,440 (85.1%)
```

검증
- 투영 박스가 프레임마다 펜에 정확히 붙는다 (들어올린 뒤에도 추적) — `/workspace/obb_check/vis.png`
- 카메라 랜덤화가 설정엔 있으나 실효가 작다: 에피소드별 치우침 dx 6.5 / dy 4.8 px
  < 에피소드 안 흩어짐 dx 7.9 / dy 12.9 px
- **축정렬 종횡비 1.92 → 회전 박스 6.42.** 같은 펜인데 축정렬은 큰 네모, 회전 박스는 펜 자체

덤: 투영 GT 기준으로 어제 뽑은 YOLO 라벨을 채점하니 **13% 가 다른 물체**(숟가락 등)였다.
YOLO 라벨로 학습했으면 그 오염이 그대로 들어갔다.

## θ 손실 가중 — 임계값 없이

동그란 물체는 "긴 변 방향"이 정의되지 않는다. 박스의 **이심률**을 그대로 가중치로 쓴다.

```
w_theta = sqrt(1 - (h/w)^2)
  펜      h/w = 0.17  ->  0.986   (거의 전부 학습)
  beaker  h/w ~ 1.0   ->  ~0      (자동으로 꺼짐)
```

라벨 자체의 불확실성이 가중치가 된다. 하드코딩된 숫자가 없다.

## ★ 지름길 — 이걸 안 막으면 결과를 못 읽는다

**이미지를 안 봐도 박스를 꽤 맞힌다.**

```
                          중심오차 중앙값 (집기 전, 조준이 중요한 구간)
상수(평균) 예측                 61.8 px
로봇 state 14축 선형회귀         26.2 px   ← 이미지 안 봄
펜 박스 긴 변                  136.5 px  (참고)
```

정책이 이미 펜 쪽으로 팔을 뻗고 있어서 **팔 자세가 펜 위치를 알려준다.** 순환이다.
모델이 이 지름길만 타면 loss 는 내려가는데 **조준 오차는 그대로**다.

### 그래서 평가를 이렇게 한다

1. **state-only 기준선 대비** — 박스 오차가 **26.2 px 보다 확실히 작아야** 비전을 쓴 것
   (태스크마다 데이터에서 다시 계산하는 **절차**다. 상수가 아니다)
2. **이미지 가림 ablation** — `image_mask` 를 끄고 오차가 거의 안 늘면 비전을 안 쓴 것
3. **두 지표를 분리해서 본다**
   - 박스 예측 오차 (grounding)
   - 펜 들림 비율 (현재 11/100)

   1 은 좋은데 2 가 안 오르면 "grounding 은 됐는데 action 이 못 쓴다" — 다른 처방이 필요하다는 신호.

## 10개 태스크 확장

| | |
|---|---|
| `*_pose` 관측 있음 + cam_high 고정 | **7/10** — 같은 코드가 그대로 돈다. 물체 uid·메시는 config 에서 읽는다 |
| `*_pose` 없음 | **3/10** (click_bell, handle_basket, table_rearrangement) — 시뮬레이터 GT 마스크나 탐지기 필요 |

회전 범위는 **대칭 물체만 −180~180** 이다 (beaker 종횡비 1.08, cube 1.01).
각도가 의미 있는 물체는 전부 좁다 (pen ±30, pipette ±30, fork/spoon ±45, rack 0~90).
우연이 아니라 설계다. 이심률 가중이 이걸 자동으로 처리한다.

**위 가중치·기준선은 전부 학습/평가 쪽이다. 추론 때는 쓰이지 않는다** —
모델은 토큰만 뱉는다. 대회 eval 세팅과 무관하다. 맞춰야 할 것은 프롬프트 형식 하나.

## 최종 형식 — PaliGemma 원형식 4토큰 (회전 버림)

5토큰(cx,cy,w,h,θ)에서 **PaliGemma 사전학습 형식 그대로**로 바꿨다.

```
Pen:<loc0296><loc0916><loc0492><loc1023>; Subtask: ...
     ymin      xmin      ymax      xmax
```

**각도를 버려도 되는 근거 (실측 84,179 프레임)**
가는 물체의 축정렬 박스는 "물체가 이 박스의 대각선을 따라 놓였다"는 뜻이다.
올바른 대각선을 고르면 각도 복원 오차 **중앙값 6.1도**(90% 9.2도).
잃는 것은 각도 전체가 아니라 **어느 대각선이냐 1비트**이고, 그 1비트는 모델이
이미지를 보면 풀린다. 박스의 일은 "어디를 볼지 좁히는 것"이다.
(항상 한쪽 대각선만 고르면 오차 29.7도 — 1비트가 전부라는 뜻이다.)

**부수 효과**
- 축정렬 박스는 둥근 물체에도 잘 정의된다 → **이심률 가중·대칭 판정이 통째로 불필요**
- 어휘뿐 아니라 **의미와 순서까지** 사전학습을 재사용한다
- 토큰 4개라 슬롯이 짧다

순서가 `y` 먼저다. 직관과 반대라 틀리기 쉽다.

## 손실

subtask 슬롯과 **같은 CE** 다 (`token_loss_mask` 가 두 슬롯을 모두 덮는다).
v1 은 두 슬롯에 같은 가중치(`PI05_SUBTASK_W`)를 쓴다 — 따로 주려면 per-token
가중치 배열이 필요한데 `Observation` 에 필드를 더해야 해서 미뤘다.

CE 에는 좌표 사이 거리 개념이 없다 (`<loc0401>` 과 `<loc0900>` 을 똑같이 벌준다).
다만 PaliGemma 가 이 토큰들을 **검출 형식으로 사전학습**해서 인접 loc 임베딩이
이미 가깝다. 기본 CE 로 시작하고, 인접 토큰에서 흔들리면 soft target 을 고려한다.

박스가 안 보이는 프레임(15%)은 슬롯이 패딩이고 loss 에서 빠진다.

## 2026-10-06 추가 — 손목 카메라 슬롯 · "박스 없음" CE · 집기 가중

### 1차 bbox 학습 결과 (H100 batch 32, 1 epoch, step 10661)

| 도달 단계 | 기존 subtask | MEM+mistake | **+bbox** |
|---|---|---|---|
| 아무것도 | 89% | 85% | **44%** |
| 1 들기 | — | 5% | 13% |
| 2 중앙이동 | — | 4% | **22%** |
| 3 holder 위 | — | 1% | **16%** |
| 4 삽입 | — | 5% | 5% |
| 펜 들림 | 11/100 | 15/100 | **56/100** |
| 공식 성공 | 1/100 | 0/100 | **3/100** |

펜 들림 CI 가 겹치지 않는다 (46.2~65.3% vs 9.3~23.3%).

**다만 박스 정확도는 기준선 미달이다.**
```
중심 오차 중앙값 29.2 px   >  state-only 기준선 26.2 px
IoU 중앙값 0.441 · >0.5 41% (전체 GT 대비 30%)
박스를 낸 호출 73% — 27% 는 <loc> 아닌 토큰 (BOS 526회, 'Sub' 300회)
```
성능은 올랐는데 박스는 기준선을 못 넘었다 — 명시적 grounding 보다
**보조 과제가 비전 표현을 다듬은 효과**일 수 있다. 구분하려면 이미지 가림 ablation 이 필요하다.

### 고친 것 세 가지

**① "박스 없음" 을 가르친다** (`apply_bbox_nobox.py`)
펜이 화면 밖인 14.9% 를 pad 로 두고 CE 에서 뺐었다. 그러면 "그 자리에 무엇을
넣어도 벌점이 없다" 를 15% 학습시킨다 — 추론 27% invalid 의 유력한 원인이다.
visible 을 3상태로 바꿨다: `1`=실제 박스, `2`="박스 없음"(<loc0000>×4 로 가르침),
`0`=추론 빈 슬롯. 네 칸 모두 0 은 ymax<=ymin 이라 실제 박스로는 안 나오는 값이다.

**② 손목 카메라 슬롯** (`wrist_bbox.py`, `apply_bbox_wrist.py`)
```
State: ...; Mistake: false; Pen:<4> Wrist:<4>; Subtask: ...;\nAction:
                            cam_high  cam_right_wrist
```
손목은 `right_link6` 에 붙어 있어 매 프레임 qpos 로 **순기구학**을 푼다
(pinocchio + CobotMagicWithGripperV100 URDF).
규약은 탐색으로 확정했다 — quat **wxyz** + 축 변환 `diag(1,-1,-1)`(OpenGL→OpenCV).
접근~집기 40/40 프레임이 화면 안에 들어오고 실제 영상과 일치한다.

두 뷰가 **상보적**이다 (327,000 프레임 실측):
```
cam_high 만  10.9%   손목 만  14.8%   둘 다 74.2%   둘 다 없음  0.0%
구간별   왼팔운반 high 70% / 손목 100%     꽂기 high 79% / 손목 56%
```

**③ 집기 구간 손실 가중** (`apply_grasp_weight.py`)
성패를 가르는 '그리퍼 닫기' 가 데이터의 **4.9%** 뿐이다 (327 중 16 프레임).
`grasp_window=(50, 113)`(lower~lift) 에 `PI05_GRASP_W` 를 곱한다.
오버샘플링이 아니라 가중이라 이미지가 반복되지 않는다.
