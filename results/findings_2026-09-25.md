# 손실 마스킹 철회 — 그리퍼는 과소가중이 아니었다

## 현재 코드에 마스킹은 없다 (확인)

```
policy/pi05/src/openpi/models/pi0.py:214
    return jnp.mean(jnp.square(v_t - u_t), axis=-1)     # 32축 전부 평균
policy/pi05/scripts/train.py:150-151
    chunked_loss = model.compute_loss(...); return jnp.mean(chunked_loss)
policy/pi05/src/openpi/transforms.py:328-337
    class PadStatesAndActions:  state/actions 를 14 → 32 로 0 패딩
```
어디에도 마스크가 없다. 14 실축 + 18 제로패딩이 같은 자격으로 평균된다.

## 그런데 마스킹해도 달라지는 게 없다

패딩 축은 `action=0` 이므로 `x_t = t·noise`, `u_t = noise`. 모델은 `t` 를 입력으로
받으므로 `v_t = x_t / t` 로 **정확히 맞출 수 있다.** 즉 노이즈가 아니라 자명한 과제이고,
학습 초반에 풀린 뒤로는 기여가 0 으로 수렴한다.

18축을 빼면 손실이 32/14 = **2.29배 균일 스케일링**된다. AdamW 는 기울기의 균일
스케일에 불변이다. **축 사이의 상대 비중은 하나도 바뀌지 않는다.**
바뀌는 것은 (a) 로그에 찍히는 손실 값, (b) 패딩 축이 아직 안 풀린 학습 최초 구간뿐이다.
82k 스텝 학습에서는 무의미하다.

## 게다가 그리퍼는 원래 큰 축이었다

축별 손실 몫은 균등(1/32)이 아니라 **타깃 분산에 비례**한다. 학습과 같은 변환
(청크 delta + q01/q99 정규화)을 재현해 items_handover 20 에피소드, 타깃 277,000개로 측정:

| dim | 분산 | 14축 중 | 32축 손실 중 |
|---|---|---|---|
| 0–5 (좌완) | 0.091–0.196 | 2.7–5.8% | 1.2–2.5% |
| **6 (좌그리퍼)** | **0.819** | **24.2%** | **10.6%** |
| 7–12 (우완) | 0.115–0.161 | 3.4–4.8% | 1.5–2.1% |
| **13 (우그리퍼)** | **0.967** | **28.6%** | **12.5%** |

그리퍼가 0/1 이라 정규화 후 전 구간을 쓰는 반면 팔 delta 는 좁은 대역에 몰려 있다.
**좌그리퍼는 14축 중 두 번째로 큰 축이다.** 2026-09-23 에 내가 "3.1% 라 못 배운다"고
쓴 것은 1/32 을 그대로 갖다 쓴 것이고 틀렸다.

→ **손실 가중치 문제가 아니다.** 남는 설명은 누적 오차(covariate shift) 하나이고,
처방은 DAgger 다. 도구: `ds_audit/loss_share.py`

한계: 분산 몫은 손실 몫의 정확한 값이 아니라 비례 지표다(흐름매칭 잔차 ∝ 조건부 분산).
q01/q99 도 체크포인트 norm_stats 가 아니라 이 표본에서 다시 계산했다.
